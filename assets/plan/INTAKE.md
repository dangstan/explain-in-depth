# Application intake

G5-01 turns the user request and available context into this completed record. Use unknown, not invented values. Ask only for a missing answer that materially changes scope or prevents correct work; continue independent preparation while it is pending.

## Required before production

| Field | What to record |
| --- | --- |
| Application | Topic or project, concrete reason for the explanation and intended use |
| Boundaries | Included subjects, excluded material, finite release size |
| Sources | Supplied paths or URLs, authority, date or version, access limits and permitted additional research |
| Readers | Prior knowledge, purpose, likely misconceptions, language and accessibility needs |
| Outcomes | What the audience at each of D1-D5 should explain, predict, distinguish or locate |
| Medium | Website, document, slides, diagram set, workshop or combination |
| Destinations | Exact local paths or document identities for outputs and source access |
| Existing material | What can be reused, adapted, replaced or must be preserved |
| Authorization | Allowed edits, previews, research, runtime execution and external publication, if any |
| Validation | Tools available, relevant render or runtime checks, reviewer arrangement, audience testing if required |
| Scope decisions | All five depths for every in-scope subject; subject boundaries, medium, requested companions and release conditions |

## Defaults that can be adapted

- One coherent example per subject, pilot first. All five depths are mandatory, not an adaptable default.
- Use the existing delivery medium when it meets the audience need; otherwise choose the simplest accessible medium that does.
- Qualitative value when no measured benefit is supported.
- Single writer with fresh independent review; no presumed model or tool provider.
- Local, reversible artifact preparation within the user's scope. Do not infer authorization for paid execution, source-system mutation or publication.
- Three unsuccessful review cycles per item before a concrete blocked report; an explicit application policy can choose another finite limit.
- Expert acceptance is the default completion target. Audience tests and timed rehearsals are separate unless the request requires them.

## Source and preservation classification

Classify each relevant existing artifact as immutable source, preserved original, editable explanation, generated output or external reference. State why it is in that category.

For local immutable files, record content hashes and compare before closure. For editable originals that must remain available, preserve the authorized original version first. For external sources, record version/date and locator; do not promise byte stability or copy content without an appropriate basis. Do not overwrite an old baseline to hide a mismatch.

Inventory existing detailed maps and their adequacy. Each in-scope subject requires a D5 visualization or map. If none is suitable, include map creation in the task scope. A topic with competing interpretations may need parallel visual paths with source references. If key evidence is inaccessible, record gaps and bound the map honestly; do not invent an exact implementation or substitute a source index for the map.

## Intake output

Write run/INTAKE.md, run/SOURCES.md, run/PROTECTION.md and run/CLAIMS.md. Initialize run/STATUS.json from the concrete bootstrap cards. Populate CURRENT_STATE.md with the selected item, role, ownership and evidence pointers. Record consequential defaults and unresolved decisions in DECISIONS.md.
