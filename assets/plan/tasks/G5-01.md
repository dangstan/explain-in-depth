TRACK: explain-in-depth
ITEM: G5-01
Role: builder
Requires accepted: None; requires a target subject from the user request or destination context

## Required context

[intake](../INTAKE.md), [routes](../ROUTES.md), destination instructions, user brief and narrowly scoped source inventory.

## Owned deliverables

- run/INTAKE.md
- run/SOURCES.md
- run/PROTECTION.md
- run/CLAIMS.md
- run/STATUS.json
- CURRENT_STATE.md and ROUTES.md application binding
- TRACK metadata in bootstrap task cards, only if binding a different instance slug

## Steps

1. Resolve the target subject, purpose, workspace and authorization from the request and available context. If the subject itself is absent, obtain it before making subject-specific claims.
2. Inspect bounded supplied sources and existing explanations; record authority, dates, conflicts and gaps.
3. Classify existing artifacts and capture appropriate preservation identities. Do not import another project's baseline.
4. Resolve audience assumptions, medium, output scope, required studies or rehearsals, review capability and finite attempt limit.
5. Initialize bootstrap ledger entries as pending, with this item in progress and unresolved production dependencies explicitly marked. Bind identical TRACK values across state, routes and cards.
6. Freeze the intake candidate, write actual evidence, mark this item awaiting_review and hand off the same ITEM.

## Deliverables

A completed intake, source and protection inventories, initial claim ledger and truthful application state.

## Acceptance

- The subject and writable scope are concrete; defaults and unknowns are explicit.
- Source inventory supports the proposed explanation or identifies specific dependent blockers.
- No output implementation, source execution or study is falsely reported.
- Initial state has no fabricated reviews; unresolved dependency entries are not eligible.

## Evidence and stopping

Follow [execution protocol](../EXECUTION_PROTOCOL.md) and [review contract](../REVIEW_CONTRACT.md). Own only the listed deliverables plus this item's evidence, ledger fields, matching CURRENT_STATE entry and relevant dated decisions. Preserve unrelated work and protected sources. Never self-accept. Keep attempts and verdicts; stop at the finite limit recorded during intake.
