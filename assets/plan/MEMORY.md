# General plan memory

- Five depths mean different reader purposes, not five amounts of jargon.
- D2 is orientation and judgment; it need not be an executive sales pitch.
- D4 is domain expertise; it need not be software architecture.
- D5 is a mandatory detailed visualization or map, linked to precise evidence. Create one if no suitable map exists; a source guide alone does not satisfy it.
- Static comparisons can reveal mechanisms. Unnecessary interactions add work without teaching.
- A chronology is not proof of causation; a passing test is not proof of audience learning.
- Preserve application-specific immutable artifacts; do not inherit the first plan's protected-file list.
- Bind a finite subject inventory and concrete task dependencies before production.
- Keep state in governed documents and the execution ledger. Handoff prompts only route the session.

- All five depths, D1-D5, are mandatory for every in-scope subject. A session or companion can focus on one depth, but integration and closure require separate acceptance of all five.
