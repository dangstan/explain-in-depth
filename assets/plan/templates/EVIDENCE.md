# Evidence record schemas

These are schemas for application records, not evidence that work has occurred.

## Source inventory

For each source: stable source ID, path or URL, precise section, version or date, accessed date when relevant, evidence type, scope, authority and known limits. Note whether original bytes are preserved or only an external locator is available.

## Claim ledger

For each material claim: claim ID, proposed wording, subject/depth, source IDs and sections, status (supported, disputed, inferred, illustrative or unsupported), local qualification, and affected outputs. Remove or narrow unsupported material claims before acceptance.

## Protection inventory

For each protected artifact: identity, classification and reason, baseline date/version, hash where appropriate, permitted wrapper changes, check method and discrepancy status. Never silently update a baseline to match an accidental edit.

## Build record

Record TRACK, ITEM, role, attempt, audience, exact candidate, owned changes, supporting source/claim IDs, design rationale, checks actually run, observed results, renders/screenshots where appropriate, preservation result and missing evidence.

## Review record

Record reviewer/context identity when available, TRACK, ITEM, attempt, exact inspected candidate, sources independently read, actual observations, instructional judgments, limitations, verdict and bounded repairs. Separate learner outcomes and measured duration from expert expectations.

## Closure record

Record final output destinations, included and excluded subject scope, accepted candidates and reviews for all five mandatory depths of each subject, source/protection status, observed artifact behavior, expert judgment, actual audience testing, timed rehearsal if relevant, unresolved limits and finite stop. Do not claim execution or publication that did not occur.
